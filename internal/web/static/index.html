How to read these numbers

The 7-day view has 168 hourly buckets, including overnight hours and weekends; 30 days are shown by day, and 12 or 24 months by week (Monday–Sunday), aligned to the display timezone. The last bucket is the current partial period. Data is collected hourly: periods after the latest collection, or before history collection began, are faded rather than shown as quiet. Groups combine their members, including every merged identity of each person. PR and commit views overlap; their totals should not be added together.

Tasks count as completed when entering “ready for qa test build”, “ready to test”, or “closed” from outside that set. Moving between those states does not count again. A reopened task may complete again. Attribution uses the assignee in the event revision.

Commit time is Git committer time; the contributor is Git author. Merge commits are excluded from commit totals and churn. Binary line statistics and unavailable PR snapshots are marked incomplete. Historical deleted or force-pushed branches may be unavailable during initial backfill.

Work areas classify each changed file by editable path rules (for example firmware/ → Firmware, .vhd files → FPGA & hardware, node_modules and vendored SDKs → Vendored). A commit touching several areas contributes its lines to each; in the commit chart it counts once, in the area where it changed the most files.

Git authors without a matching Azure identity appear with “(Git)”. Activity attributed to a person does not distinguish manual work from agents using that account. “AI co-author markers” counts commits whose message carries an AI co-author trailer or tool banner; many people strip these, so it is a lower bound, not a measure of AI use.
